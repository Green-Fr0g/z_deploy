# 策略配置

`<robot>/<policy>/config.yaml` 中的 `commands_scale` 控制摇杆正反方向的指令幅值，
顺序固定为 `+x, -x, +y, -y, +yaw, -yaw`。其中 yaw 是绕 Z 轴转动，不是竖直移动。
模型接收的 `commands` 仍为三维 `[vx, vy, yaw]`，无需修改观测维度。

```yaml
# 示例：前进幅值 1.5，后退幅值 0.5；所有方向都填写非负数。
commands_scale: [1.5, 0.5, 0.4, 0.4, 1.0, 0.8]
```

摇杆先限制到 `[-1, 1]`，再按方向选取幅值。例如 x 输入为 `-0.5`，上例输出为 `-0.25`。
`0` 可以禁用对应方向。幅值表示策略指令范围，实际速度取决于策略和训练时的指令定义。

| 配置 | 行为 |
| --- | --- |
| 未配置或 `[]` | 默认六个方向均为 `1.0` |
| 标量 `0.5` 或 `[0.5]` | 六个方向均为 `0.5` |
| 旧三维 `[x, y, yaw]` | 展开为 `[x, x, y, y, yaw, yaw]` |
| 六维数组 | 按指定方向使用 |
| 其他长度、非数值、负数、NaN、无穷大 | 配置加载失败，策略不启动，FSM 返回 Passive |

运行时某一路摇杆出现 NaN 或无穷大，只将该轴指令清零，其余轴继续正常处理。
配置加载失败时，加载器保留上一份有效配置，但不会自动继续运行上一策略。

## 观测与推理周期

观测和推理使用两个独立线程，周期由配置组合决定：

- `base.yaml` 的 `dt`（可由策略配置覆盖）：观测采样周期，只刷新“当前帧”。
- 策略的 `decimation`：推理周期为 `dt × decimation`，历史帧在每次推理时推进一帧。

例如 `dt: 0.005`、`decimation: 4` 表示观测 200 Hz、推理 50 Hz；
`dt: 0.01`、`decimation: 3` 表示观测 100 Hz、推理约 33.3 Hz。

观测线程不断更新时间戳最新的一帧，不推进历史。推理线程每次先取最新帧压入历史、
拼出完整观测，释放锁后执行模型；推理较慢时观测继续刷新当前帧，历史只在推理步上
前进，不会堆积旧帧。观测中的 `actions` 使用采样时最近一次完成推理、处理过限幅的
动作。

`observations_history` 的索引按**推理步**计数，`0` 表示最新一帧，与训练环境每个
policy step 采样一次的语义一致。例如 `dt: 0.005`、`decimation: 4` 时：

- `[4, 3, 2, 1, 0]`：当前及 20、40、60、80 ms 前的五帧（5 帧历史）。
- `[3, 2, 1, 0]`：当前及 20、40、60 ms 前的四帧。

运动参考时间也按每次观测更新推进 `dt`。参考动作按动作 yaml 里的 `csv_fps` 实时播放；
未配置 `csv_fps` 时回退到推理步频 `1 / (dt × decimation)`，即假设 CSV 每个推理步一行。
停止或切换策略时会停止两个线程，
清除观测和动作缓存，避免沿用上一策略的数据。定时器为普通线程调度，实际频率受运行负载影响。
